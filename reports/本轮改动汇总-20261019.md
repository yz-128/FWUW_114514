## 一、开镜倍率（原来完全没实现）

### 问题

`ZoomLevel` 被当成单个浮点数解析，而 1.7.10 的真实格式是：

```
ZoomLevel <镜筒模型> <黑边遮罩模型> <倍率> <灵敏度> [<倍率> <灵敏度> ...]
```

`toFloat("EFTRAtt.PSO1Glass")` 抛 `NumberFormatException` 后返回 `0F`，整条倍率链丢失。全项目也没有任何 Framebuffer 或镜内渲染代码。

### 改动

| 文件 | 内容 |
|---|---|
| `common/types/AttachmentType.java` | 新增 `scopeGlassModel`、`blackMaskModel`、`fovZoomLevels[]`、`mouseSensitivityMult[]`、`zoomStep`；重写 `ZoomLevel` 解析；新增 `zoomDivisor()` / `sensitivityMultiplier()` |
| `client/GunDetails.java` | `ViewportEvent.ComputeFov` 接入倍率，按 `AimState` 进度平滑过渡；带按枪栈 + 修订号的缓存，避免每帧遍历配件树 |
| `client/render/LegacySightPose.java` | 新增 `selectedType()`，返回当前瞄准的瞄具类型 |

### 标定结果

`pupilDistance = 0.1` 时，EFT 内容包自己写的数字正好还原成命名声称的倍率：

| 瞄具 | 原始值 | 结果 |
|---|---|---|
| PSO1 | 40 | 4.0× |
| NF7x | 70 | 7.0× |
| G33Enabled / G33Disabled | 39 | 3.9× |
| PU35RifleScope | 35 | 3.5× |
| SeecterDR1x4x | 48.75 / 15.5 | 4.875× / 1.55× |

## 二、开镜速度（原来固定每 tick +0.2）

### 关键纠正

`AimTime` **不是时长**，是每 tick 的**保留系数**。原版公式：

```java
zoomProgress = 1F - (1F - zoomProgress) * aimTimeConst;   // 开镜
zoomProgress *= aimTimeConst;                              // 收镜
```

值越小开镜越快。我最初按"时长"理解，读了 FMUM 源码后重写。

### 改动

| 文件 | 内容 |
|---|---|
| `client/AimState.java` | 改为保留系数模型，默认 `0.66`（1.7.10 原值）；`setRetention()` / `retention()` |
| `common/GunStats.java` | 新增 `aimTimeMultiplier()` / `moveSpeedMultiplier()`，递归乘积整棵配件树 |
| `client/GunAnimationDriver.java` | 每 tick 用 `枪 AimTime × 全部配件 AimTimeMult × 瞄具 onUseAimTimeMult` 设定速率 |
| `common/types/AttachmentType.java` | 补解析 `AimTimeMult` / `MoveSpeedMultiplier` / `SightSwitchMult` 的第二个数值（原版的*使用中*值）；新增 `onUseAimTimeMult`、`onUseSightSwitchMult`、`aimingMoveSpeedMultiplier` |

## 四、准点渲染（原来只解析不渲染）

### 改动

| 文件 | 内容 |
|---|---|
| `client/render/TurborigItemRenderer.java` | 新增 `renderDot()`；贴图**拼帧号**；按 `reticleScale × 0.4` 只压 Y/Z 轴；半透明混合；`FULL_BRIGHT` 自发光；一次性诊断日志 `[Reticle]` |
| `client/model/loader/BytecodeModel.java` | 补提取 `reticleScale`（PSO1=0.4、NF7x=0.0175、Kobra=0.3） |

### 三个技术点

**1. 贴图要拼帧号**

`DotModel <model> <texture> <count>` 里的 texture 是**词干**，帧号追加在后面：

```
DotModel EFTRAtt.PSO1Dot LightTexture/PSO1Dot 3
  → LightTexture/PSO1Dot0.png / PSO1Dot1.png / PSO1Dot2.png
```

直接找词干会解析失败，回退到缺失贴图，渲染成**品红色**。这是最初那个紫色轮廓的直接原因。

**2. 用半透明混合而非 cutout**

原版是 `glowOnStatic`：关光照、开混合。准点贴图差异极大：

| 贴图 | 尺寸 | 内容 |
|---|---|---|
| `CobraEKPrefiexSightDot0.png` | 32×32 | 1 个纯红像素 |
| `PSO1Dot0.png` | 512×512 | 146502 个不透明 + 12392 个半透明像素 |

cutout 会丢弃半透明边缘和任何 alpha < 0.5 的像素，对这两类贴图都不合适。

**3. 位置机制与原版一致**

原版 `RenderGun.java:208-215`：

```java
vec = sightModel.reticleAt[k];
tempSightCoors.oriDotCoors[k].set(atPos.x + vec.x, ...);
```

准点画在 **挂点位置 + `reticleAt`**。而 `ModelAtSight.reticleAt` 默认是原点，Kobra 的模型类没有设这个字段（只设了 `reticleScale` 和 `reticleBorder`），所以原版也是画在挂点原点。当前实现完全一致。

### 我在这里犯过的两个错（均已修正）

**错误 1：加了两道原版没有的门槛**

```java
if(!isSelectedSight(motion.gun, at)) return;   // 只画选中的
if(aimProgress() < .5F) return;                // 只在开镜后画
```

原版循环遍历 `allSightsCoors` 里的**每一个**瞄具，并且在 `renderGunFP()` 之后**无条件执行**——只要第一人称渲染就画，与是否开镜无关。这两道门槛导致腰射时准星完全消失。

**错误 2：把 `reticleScale` 默认值从 0.4 改成 1.0**

原版 `ModelAtSight.reticleScale` 默认就是 `1F`。而且真实瞄具都自己声明了值，改默认值对它们毫无影响。已改回 1.0。

## 七、蛋壳物理（原版没有任何碰撞）

### 原版事实

`GunCase.java` 只有重力和阻尼：

```java
velocity.y += G_ACCELERATION;      // -1.96F/160F
velocity.scale(V_FRICTION);        // 0.99
rotVelocity *= RV_FRICTION;        // 0.99
```

**没有任何地形碰撞**——蛋壳直接穿地掉下去，`caseTime` 到时消失。所以"物理效果"是新增能力，不是恢复原版行为。

### 改动

| 文件 | 内容 |
|---|---|
| `client/model/FmumCasing.java` | 逐轴方块碰撞、反弹、地面摩擦、静止判定、嵌入保护；寿命 ×4 |
| `client/render/MuzzleEffectsRenderer.java` | 蛋壳移出手部 pass；光照改用所在位置；上限 128 → 256 |

### 物理参数

| 常量 | 值 | 含义 |
|---|---|---|
| `GRAVITY` | `-1.96/160` | 原版值，未改 |
| `AIR_DRAG` | `0.99` | 原版值，未改 |
| `GROUND_FRICTION` | `0.55` | 新增：落地后水平衰减 |
| `GROUND_SPIN_FRICTION` | `0.6` | 新增：落地后自旋衰减 |
| `BOUNCE` | `0.32` | 新增：反弹系数 |
| `SLEEP_SPEED` | `0.004` | 新增：静止阈值 |
| `RADIUS` | `0.02` | 新增：碰撞检测半径 |

### 三个必须说明的处理

**1. 移出手部渲染 pass**

原来第一人称时蛋壳画在**手部 pass** 里。原版为了让手里的枪不插进地形，会在画手之前**清空深度缓冲**，所以这个 pass 里画的东西都会盖在世界之上——蛋壳因此能透过树看见，并且用的是手部光照（夜里渲染成黑色碎片）。

现在无论第一人称还是第三人称，都在 `RenderLevelStageEvent.AFTER_PARTICLES` 绘制，深度测试生效。

**2. 光源改用蛋壳位置**

```java
int caseLight = mc.level == null ? FULL_BRIGHT
        : LevelRenderer.getLightColor(mc.level, BlockPos.containing(entry.origin));
```

蛋壳在暗处就是暗的，在灯下就是亮的。

**3. 嵌入保护**

贴墙开枪时蛋壳可能生成在方块内部。三个轴的碰撞检测会同时判定受阻，把它**永久焊死在墙里**。现在加了一道前置判断：已在方块内的蛋壳忽略碰撞，自然飘出来。

### 寿命

所有 EFT 枪模型的 `caseTime` 都是 **60 tick**（实测 12 把枪确认）。乘以 `LIFETIME_MULTIPLIER = 4` 后为 **240 tick（12 秒）**。

用乘法而非固定值，内容包写短写长都会按比例延长。

**顺带修了一个会吃掉效果的问题**：蛋壳列表上限原本是 128。寿命延长 4 倍后高射速武器很容易顶到上限，新蛋壳会把**还在飞的**老蛋壳挤掉。已提高到 256。

## 需要知道的近似与缺口

### 两个 `pupilDistance` 常量

原版是同一个实测值（眼睛到瞄具镜片的距离），但这个移植没有重建镜片坐标，所以拆成两个各自标定：

| 常量 | 值 | 用途 |
|---|---|---|
| `DEFAULT_PUPIL_DISTANCE` | `0.1` | 倍率：这个值下 EFT 数字才对得上命名 |
| `RETICLE_PUPIL_DISTANCE` | `0.4` | 准点尺寸：`0.1` 会缩到不足一像素 |

准点太小或太大，调后者即可。

- 激光 / 手电模型渲染（各 1 个文件声明）
- 配件涂装（paintjob）只存不用
