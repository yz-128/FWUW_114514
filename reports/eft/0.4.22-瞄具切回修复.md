# 0.4.22 · 已展开的 G33 折不回去

2026-10-20。用户反馈：腰射状态下 G33 已经翻上来（截图里 EOTech 后面那只放大镜），按折叠键没反应。

## 复现

离线搭同一套装配（AK74M + `SVDLowSideMount` 槽位 6，槽位 0 内 `EOTech552` + `G33Enabled`）：

```
groups=3
  g0 aiming=G33Enabled   y=0.484 z=0.000 x=-0.056
  g1 aiming=EOTech552    y=0.485 z=0.000 x=-0.056
  g2 aiming=6P1Sb2AK74Rearsight

选中全息镜组 g1 → canChange(TOGGLE) = false   ← 折不回去
```

## 原因

上一版（0.4.20）只修了"折叠 → 展开"这个方向：`toggleTargets` 第二级只遍历 **`isFoldedVariant()`** 的镜子。

```java
for(var sight:all)if(sight.type.isCoSight() && sight.type.isFoldedVariant()) { ... }
```

展开后的 `G33Enabled` 不是 folded variant，所以：
- 它自己成一组（`y=0.484` vs 全息镜 `0.485`，差 0.001，远超 1e-5 的共线容差）；
- 在全息镜组里按折叠键时，第一级（组内 cosight）够不到它，第二级（folded）又不看它；
- 结果 `canChange(TOGGLE)=false`，按键静默无效。

同一挂位、同一个物理件的两个状态，**两个方向都要能切**。

## 修改

`GunSightState.toggleTargets` 第二级改为遍历**所有声明了 shadow 的 cosight 镜**，不再要求当前是折叠态：

```java
for(var sight:all)if(sight.type.isCoSight()) {
    var shadow=AttachmentType.getAttachment(sight.type.shadowType);
    if(shadow==null)continue;
    if(sight.type.isFoldedVariant() && sameLine(group.aiming,shadowPoint(sight,shadow))) {result.add(sight);continue;}
    if(sameMount(group.aiming,sight))result.add(sight);   // 同挂位的声明配对，折叠/展开都算
}
```

- 折叠态仍然优先用"展开后共线"这条精确路径；
- 展开态（以及共线判不准的折叠态）走同挂位配对，双向都成立。

## 回归

`VerifyGunSightState` 在原有"折叠→展开"用例之后追加 **展开→折叠** 的 4 条断言：

- 展开态下全息镜组可选；
- 该组里 `canChange(TOGGLE)` 必须为真；
- 触发后节点定义回到真实 `G33Disabled`。

单包运行 63 → **67**；审计脚本双包运行时为 **79**。
