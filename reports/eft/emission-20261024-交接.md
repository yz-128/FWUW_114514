## 已重新确认的事实

### 1. 当前 45 个原包 glow 模型全部能够识别

独立 ASM 扫描 `run/flan`（排除 `_disabled`）的 **1122 个 class**：

| 检查 | 实际数量 |
| --- | ---: |
| 任一方法中有 glowOn / glowOnStatic 的类 | 45 |
| 直接在 render(F)V 中调用 glow 的类 | 45 |
| render(F)V 通过同类 helper 间接进入 glow，当前入口漏检的类 | 0 |
| 继承另一个包内模型 render(F)V 而漏检 glow 的类 | 0 |
| 同名但内容不同的 class | 0 |

随后用当前 modern 最终 JAR 的真实 `BytecodeModel.fromFile` 读取全部 class：**45/45** 均生成 256 个模式的发光 profile，`emissiveRenderUnsupported=0`，profile 遗漏=0。这次运行只执行移植后的字节码解析器，没有加载执行原包旧类。

因此，“仅扫描声明的 render(F)V、没有 helper/继承递归”是扩展兼容性的边界，但在当前原包上不是已经发生的漏识别故障；不要为了一个没有原包证据的猜测重写解释器。

### 2. 与 1.7.10 的发光语义一致

参照 `FMUM-1710-master/src/main/java/com/flansmod/client/model/ModelFlan.java`：

- `glowOn()` 等同于强度 15；`glowOn(int)` 给 block/sky lightmap 分别增加强度对应值并封顶 240。
- `glowOnStatic()` 设置 240/240；`glowOff()` 恢复先前值。
- 这套调用本身没有取消方向光，也没有使环境产生动态照明。

当前 `GlowLight.apply`、普通附件与发光附件分组、折叠状态材质和 GUI 路径已有相应实现。不能凭 `lightModel` 字段名或图片名包含 light 就让模型常亮；不能将所有旧 glow 直接替换成无方向明暗的 emissive shader，再宣称与 1.7.10 等价。

### 3. 新发现：普通皮肤及弹头皮肤缺少按来源隔离

`Textures.forType(InfoType)` 只取 `type.texture`，`Textures.of` 的缓存键只有字符串和默认弹头标志，忽略 `type.contentPack`。`TurborigItemRenderer.renderSeatedRounds` 同样直接调用 `Textures.of(seated.bulletTexture,false)`，也丢失弹药来源；`ModelCache` 随后以全局选中图片尺寸修正 UV。因此同名皮肤冲突可以同时影响图像与 UV。

实际扫描 **612 个 skin 相对路径**，发现 **48 个同名但 SHA256 不同**；其中 36 个被当前视觉定义字段引用，共 128 行。这里只列出原文件引用事实，尚未据此断言每条定义都能穿过重复 ShortName 覆盖并成为最终注册物品：应补一个实际注册定义的来源测试再界定受影响物品。

具体证据：

- `assets/flansmod/skins/556x45mm.png`：Reforged 为 **64×64**，旧 EFT Guns 为 **2048×2048**；两套 `BulletModel` 都使用该名称。`9x19mm`、`762x51mm`、`46x30mm` 等同样存在。
- `skins/lighttexture/defaultdot0.png` 在 EFT Reforged/Octagon 为 **32×32 / 64×64**，但 `ReticleResources` 已处理分划的来源隔离，不能把这个已处理的路径重新算作未修缺陷。
- `skins/seecterdr1x4x.png` 在 Octagon/旧 EFT Guns 为 **256×256 / 512×512**。旧 EFT 的 `Model EFTatt.SeecterDR1x4x SeecterDR1x4x 0.2` 明确引用此路径；Reforged 那个对应瞄具用的是另一个 `Sights/SeecterDR1x4x`，不能混为同一引用。

现有 `ReticleResources` 和 `ArmourResources` 是可复用的来源隔离模式。不能通过更改/重打包原内容包来消除冲突。

## 建议下一步（按优先级）

1. **先修来源保持**：建立对普通模型皮肤和附加模型皮肤通用的来源解析，输入至少为 `InfoType + textureName + modelReference + 默认策略`。优先定义自身内容包，其次对应模型来源，最后保留当前全局兜底；命名空间显式资源应保留资源包覆盖契约。生成的资源 ID 应稳定并按定义/模型用途隔离，不能只把缓存键加上 pack 后仍返回同一个全局资源 ID。
2. **同时接通所有使用处**：`Textures.forType`（实际绘制与 `ModelCache` UV 查询必须一致）、`renderSeatedRounds` 的 `BulletModel`、`forMagazineFollower`、枪的额外模型皮肤与其他 `Textures.of` 用户。`GeneratedAssets` 如承担隔离资源复制，必须同步接入并正确响应资源重载。不要破坏既有 Armour/Reticle 专用隔离。
3. **补诊断而非猜测发光**：`emissiveRenderUnsupported` 目前只被离线测试读取，运行时没有按模型去重告警。可增加一次性诊断，显示类名、来源和不支持的调用原因；保持失败关闭，后续新包才不会静默丢发光。当前原包不需要为了它改解释器。
4. **最后验证来源/材质及双产物**：将下面测试绑定最终 JAR SHA256，再考虑发布下一版。不要直接覆盖 0.5.49 的历史证据。
