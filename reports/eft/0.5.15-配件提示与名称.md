# 0.5.15 · 配件提示：从"乱列配件"改回 1.7.10 的写法

日期：2026-10-21。用户问的物品是 EFT 包的枪口制退器 `6P26AKS74UMuzzleBrake`，截图中它的提示写着

```
可安装到：?20mmMosinBarrel / 6P26AKS74UDustCover / A3Adapter 等 20 种配件
```

## 一、这个物品本身

`run/flan/EscapeFromTarcraftReforged_1.5.3/attachments/6P26AKS74UMuzzleBrake.df`：

```
Name 6P26AKS74UMuzzleBrake
ShortName 6P26AKS74UMuzzleBrake
RecoilMultiplier 0.9 0.9
AimTimeMultiplier 1
Description Need:AK74 AK74N AK74M AKS774U
Model EFTRWea.6P26AKS74UMuzzleBrake Weapons/AKS74UDefault 0.2
ItsType barrel
AttachmentType AKMuzzleBrake
```

- 名字是一串编号，是因为**包里的 `Name` 就等于 `ShortName`**；1.7.10 同样显示这串编号，不是移植缺陷。
- 包里**没有** `textures/items/6P26AKS74UMuzzleBrake.png`（1.7.10 启动日志里"missing 26 textures"就包括它）。1.7.10 显示紫黑 missing-texture；移植版 0.5.6 的图标兜底会退到**模型皮肤** `Weapons/AKS74UDefault`，所以候选卡上的缩略图看起来像一把 AKS-74U 而不是一个枪口装置。

## 二、真正的 bug：提示里的"可安装到"

1.7.10 的 `ItemAttachment.addInformation`：

```java
if(!type.packName.isEmpty()) lines.add("§o" + type.packName);
if(type.description != null) Collections.addAll(lines, type.description.split("_"));   // 只显示包里的 Description
// 按住 Shift 才展开数值
```

移植版自己发明了一条"可安装到"，用 `GunAttachmentCatalog.directParents` 计算——而这个目录**只遍历附件**（`new GunAttachmentCatalog(AttachmentType.attachments)`），永远列不出枪；再加上 EFT 包里大量宽松/空白槽位白名单，结果就是莫辛枪管、AKS74U 防尘盖、A3 转接座等 20 个毫不相关的**配件**被当成"能装它的东西"。

## 三、修复

1. `ItemFlan.appendHoverText` 回到 1.7.10 的骨架：
   - 包名一行（斜体、暗灰）；
   - `Description` 按 `_` 分行（灰色）；
   - 附件的接口行保留；
   - "可安装到"改为**真正能装它的枪械**。
2. 新增 `GunAttachments.gunsAccepting(AttachmentType)`：遍历 `GunType` 定义的每个槽位，用现有的 `allowed(...)` 判定。对这把制退器的实测结果：

```
guns accepting 6P26AKS74UMuzzleBrake: [AK74, AK74M, AK74N, AKS74U, RPK16]
```

修正后提示应为：

```
6P26AKS74UMuzzleBrake
EscapeFromTarcraftReforged_1.5.3
Need:AK74 AK74N AK74M AKS774U
接口：akmuzzlebrake
可安装到：AK74 / AK74M / AK74N 等 2 种枪械
```

## 四、验证

新增 `VerifyAttachmentTooltip`（16 断言，真实内容包）：

- `Description` 解析为 `Need:AK74 AK74N AK74M AKS774U`；
- `gunsAccepting` 对该制退器恰好返回 `[AK74, AK74M, AK74N, AKS74U, RPK16]`；
- 列表里不再出现 `220mmMosinBarrel` / `6P26AKS74UDustCover` 这类配件；
- 瞄具 `EOTech553` 也能解析出宿主枪；
- 全包 > 半数的附件能解析出至少一把宿主枪（实测数量与比例在断言里）；
- 字节码：`appendHoverText` 调 `gunsAccepting`、不再调 `directParents`。

回归：`RunGunsmithAudit`（含 6 个 GPU 用例的预览深度验证）、`RunOpticsAudit -GpuChecks`、`RunImpactAudit` 全部通过，末尾哈希一致
`4E0392E600A3AE999F351B5325858655591A574215AF3FB64A84ED1EED5E8D6C`。

## 六、遗留（可选）

- 无图标配件的 UI 缩略图仍会退到模型皮肤（看起来像一整把枪）。要更准确，可以给"无图标的配件"生成通用配件图标，或用离线 GPU/CPU 光栅把 3D 缩略图烘出来；需要的话另开一轮。
- 配件显示名（`Name` 等于 `ShortName`）属于包数据，不修改 `run/flan` 的前提下无法修正，除非做"仅 UI 的名称美化"。
