# 0.5.24 · 玩法机制第一项：枪管过热

日期：2026-10-22。目标：按「默认开启、数据可覆盖、不改变基线以外的后坐力/散布」的要求，加上第一条玩法机制。

## 一、最终效果

- **连射升温**：每发加 `heatPerShot`（默认 **1.2%**），每个 tick 冷却 `heatCoolRate`（默认 **0.35%**，约 14 秒从满热降到 0）；
- **射速略降**：热量到满时射速慢 **10%**（`heatRateMult`，线性：一半热量 → 慢 5%）；这是热量**唯一**的射击手感影响；
- **过热锁火**：热量到 100% 时扳机被锁 `heatLockTicks`（默认 **40 tick / 2 秒**），锁期间开火只出空枪声；冷却完自动解锁；
- **HUD**：准星下方（血条上方）一条热度条，>2% 显示，颜色白黄→橙→红；锁火时显示红色 **过热 / OVERHEAT**；
- **不改后坐力、不改散布**（按要求移除）：`BarrelHeat` 里只有 `rateMultiplier`，没有 spread/recoil 乘子；
- **默认参数温和**：默认的 30 发弹匣打空只到 36% 热度、不会过热；约 83 发连续射击才过热。

## 二、数据键（内容包可选覆盖）

在枪的 `.df` 里（全部可选，缺省用上面的默认值）：

```
HeatPerShot 0.012      // 每发热量
HeatCoolRate 0.0035    // 每 tick 冷却
HeatRateMult 1.1       // 满热时的射击间隔倍率
HeatLockTicks 40       // 过热锁火时长（tick）
```

**全局开关**：`-Dflansmod.mechanics=off` 完全回到 1.7.10 行为（不升温、不锁火、无射速影响）。

## 六、已知限制 / 下一步

- 热量在客户端与服务端各自按 `fireRound` 预测，没有新增同步包；网络丢包/延迟下两端可能短暂不同步（单机完全一致）；
- HUD 显示双手热量的较大值，暂不分别显示左右手；
- 后续机制（磨损/故障、配件耐久等）可沿用同一套「纯函数 + PlayerData 状态 + 数据键 + 离线断言」的结构。
