## 一、镜内画面：不再裁成品画面

### 问题

0.4.4 的做法是把已经渲染好的世界画面中央裁一块、放大贴到镜片上。裁切拿不到新细节：4 倍镜只取屏宽 20%，1080p 下就是 **383×215 像素被拉到 709×391 显示**（PSO1 实测，插值 1.85 倍）。

### 三种参考实现

| 实现 | 镜内画面从哪来 | 分辨率 |
| --- | --- | --- |
| 1.7.10 FMUM | 用放大后的 FOV **第二次渲染世界**，写进固定 256×256 的 FBO | 256²（最糊） |
| TACZ 1.20.1 | **世界相机 FOV 直接除以倍率**；手持物用另一套 FOV；镜筒用模板缓冲挖孔 | 主渲染原生分辨率 |
| FMU 2.0 1.21.1 | 同上，`ModClient.cameraFov` 世界 FOV 除以倍率；镜内靠全屏 `ZoomOverlay` | 主渲染原生分辨率 |

两种现代实现都不裁帧，本版按这条路重做。

### 实现

1. **世界相机按倍率拉近**（`GunDetails.fov` + `ScopeMagnification`）。手持物 FOV 不加倍率，枪与镜保持物理尺寸，只有镜外世界被放大。
2. **镜片 1:1 采样**（`ScopeWorldTexture` + `FmumSightRenderer.renderLens`）。世界已按放大 FOV 渲染，镜片只需按每个顶点自己的屏幕位置取样，没有中心偏移、没有拉伸。
3. **必须保留镜片绘制**：EFT 瞄具在目镜处有不透明挡片（PSO1 的 `x=0.938` 端面），不画镜片会正对挡片。
4. **未选中/未开镜时镜片仍为黑**，与 1.7.10 的 `DefaultBlack` 一致。

### 倍率语义（重要）

内容包的 `ZoomLevel` 权重是**名义倍率的 10 倍**，除以 10 得到作者命名时用的倍数：

| 配件 | 包内写法 | 实际倍率 |
| --- | --- | --- |
| PSO1 | `40 0.6` | 4× |
| NF7x | `70 0.3` | 7× |
| PU35RifleScope | `35 0.65` | 3.5× |
| SeecterDR1x4x | `48.75 0.4  15.5 0.8` | 4.875× / 1.55× |
| Octagon 变倍镜 | `87.75 … 39` | 8.775× … 3.9× |

旧代码乘的是瞳距，对直装的 PSO1 恰好接近，但 **NF7x 会算成 0.70 被钳到 1 倍（等于没放大）**，CICND 的 `48.75 × 0.63` 会算成 30 倍。

## 二、开镜姿态：枢轴改用真实相机位置

### 问题

1.7.10 把第一人称相机当成枪空间常量 `(-81.5/160, 0.4, 0)`，所以 `aim()` 固定把瞄具中心平移到 `y = 0.4`。移植版照抄，但实测相机落点随枪不同：

| 枪 | 开镜时相机在枪空间的 y |
| --- | --- |
| AK74M | 0.400（刚好等于 0.4） |
| DT MDR 7.62 | 抬枪前 0.269 / 抬枪后 0.400 |

DT MDR 开镜过程中相机在 0.269 与 0.400 之间移动，枢轴却始终瞄 0.4。把瞄具原点投到屏幕得到 **NDC y = −1.99**，整个瞄具在画面上方之外——与实机截图完全一致。

### 实现

`FmumFirstPersonPose.aim(pose, sight, ads, eye)` 接受相机在枪空间的实际位置（`eyeInGunSpace`），translate / rotateX / undo pivot 结构不变。X 轴保持原样，因为那是眼距，由内容包挂点决定。

| 状态 | 瞄具原点 NDC | 眼睛相对镜框中心 |
| --- | --- | --- |
| 修复前，满开镜 | (0.067, **−1.992**) | — |
| 修复后，满开镜 | (0.000, 0.034) | **(−0.001, 0.000)** |
| 修复后，半开镜 | — | (0.051, −0.125)，预期过渡态 |

## 三、准星：选中组里的红点镜不再被跳过

### 问题

`FmumSightRenderer.render()` 原先对"当前选中组内的瞄具"直接 `return`，假设准星由镜片合成路径统一绘制。这对 PSO1/NF7x 成立，但 **CIC 没有 `ZoomLevel`、没有镜片**：`renderLens` 不会被调用，`renderDot` 又被 `return` 掉，开镜时一个准星都没有。

### 实现

判断条件从"在选中组里"改为"**这个瞄具真有镜片**"。没有镜片的瞄具无论是否选中，都走自己的 `renderDot`。

### 诊断日志

旧日志每个瞄具只打第一帧，而第一帧通常是抬枪途中（眼睛本来就该偏离光轴、准星本来就该隐藏），于是 `hits=0` 看着像 bug。现在改为**结果变化时**输出，并给出眼睛相对镜框中心的偏移：

```
[Reticle] <ShortName> ... ads=1.00 eye=(...) aperture=(...) offset=(...)
```

满开镜时 `offset` 应接近 0。

## 四、收枪判定：草不再触发

### 问题

`GunActions.nearWall()` 用 `ClipContext.Block.OUTLINE`。草、花、作物注册时带 `noCollission()`：**碰撞箱为空，但轮廓箱仍是 14×13×14 的盒子**。于是枪口对着草也会"命中方块"，自动收枪。

### 1.7.10 的做法

`ItemGun.rayTrace()` 调 `world.func_147447_a(from, to, false, false, true)`，第三个参数 `ignoreBlockWithoutBoundingBox = true`，草直接跳过。现代版的对应语义即 `COLLIDER`。

### 实现

`nearWall()` 的 `OUTLINE` → `COLLIDER`。一行。

实测判定范围（起点为枪管口，长度为 `gunLength`）：

| 枪 | `gunLength` | 腰射时枪管离眼 | 开镜时枪管离眼 |
| --- | --- | --- | --- |
| DT MDR 7.62 | 0.616 格 | 0.801 格 | 0.506 格 |
| AK74M | 1.250 格 | 0.293 格 | 0.113 格 |

## 五、收枪触发条件（完整表）

| # | 触发 | 需要按键 | 条件 |
| --- | --- | --- | --- |
| 1 | 按 **O** | 是 | 手持枪、无界面、非换弹/预换弹/预开火、瞄具未折叠 |
| 2 | 按 **Alt+V** | 是 | 同上（与 O 等价） |
| 3 | **枪口顶到有碰撞箱的方块** | 否 | `gunLength > 0` 且射线在 `gunLength` 内命中；草/花/作物不会触发 |
| 4 | **枪口离开方块**（解除） | 否 | 仅解除自动收枪；手动按 O 收的枪保持 |
| 5 | **再次按 O / Alt+V**（解除） | 是 | 切到 UNREST |
| 6 | **开火 / 换弹**（解除） | 是 | `ready()` 为 false → `resume()` |
| 7 | **切枪 / 换栏 / 换维度 / 改枪**（解除） | 否 | `ensureHeld` 检测变化后 `reset()` |
| 8 | **冲刺** | 否 | 阻止新的收枪开始，不解除已生效的 |

默认时长：`RestTime 12` tick、`UnrestTime 6` tick（所有 EFT 枪都用默认值）。

## 六、内容包核对

两个光学包的全部瞄具都检查过，`reticleBorder` 从瞄具**本体**模型读取：

```
EscapeFromTarcraftReforged_1.5.3   sight=37  有 DotModel=16  缺边框=0  缺贴图=0
OctagonWeaponsReforged_1.33        sight=16  有 DotModel=7   缺边框=0  缺贴图=0
```

三处曾被误判为"缺数据"的情况，现已确认都是正确的：

- **`RMRMicroSightPad`** 是转接底座（`extends ModelAttachment`），准星属于它上面的 `RMRMicroSight`（`extends ModelAtSight`）。
- **`14x8basesight`** 不是配件，是护木的槽位类型（`TypeWhitelist` 的一列），没有定义文件是正确的。
- **CIC 数据完整**：6 点镜框、`reticleAt = (4096, 0.028125, 0)`、`pupilRefCenter = (0.25, 0.625, 0)`、`reticleScale = 0.15`；`AimCenter 4.5`（÷16 = 0.0281）与 `reticleAt` 的 Y 完全一致。

### 新增的两个测试为什么值得留

- **VerifySightPicture 的枢轴断言**是纯数学检查，不依赖 Minecraft：把瞄准点变换后必须等于相机位置。它能直接阻止"有人把 0.4 写回去"。
- **VerifyRestWallShape** 用真实原版方块类和原版 `BlockGetter.clip`，只把世界方块存储换成内存网格。每种植物同时断言"碰撞箱为空 + 轮廓箱非空 + OUTLINE 命中 + COLLIDER 不命中"，因此同时证明了旧 bug 的成因、修复有效、以及实心方块判定没被削弱。

## 八、工具与脚本整理

- 删除临时目录 `reports/eft/zoom/`（14 份重复日志，审计脚本已在 `reports/eft/` 生成同名文件）。
- `tools/offline/InspectScopeOptics.java` 保留为**诊断工具**（只读、打印实测瞳距/裁切比例/目镜角覆盖），不参与自动审计。
- `tools/offline/RunEftAudit.ps1` 修复了三个在本机无法运行的问题：
  - Windows 命令行长度上限导致 14 KB 的 classpath 被拆断 → 改用 `@argfile`；

  - `$ErrorActionPreference='Stop'` 把 JVM 写到 stderr 的警告当终止错误 → 改为 `Continue`，仍按 `$LASTEXITCODE` 判断。
  - 新增 VerifyScopeZoom / VerifySightPicture / VerifySightAlignment / VerifyScopeReticles / VerifyCasingPhysics / VerifyRestWallShape 六个入口。
