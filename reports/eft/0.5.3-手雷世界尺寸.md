# 0.5.3 · 手雷在世界的尺寸（掉在地上的手雷太大）

2026-10-20。用户截图：投出去落地的 RGD5 / M67 各占一个多方块，明显过大。

## 原因（两层）

1. **渲染走了物品的 GROUND 变换**。第一版 `GrenadeRenderer` 用 `ItemRenderer.renderStatic(stack, ItemDisplayContext.GROUND, …)` 画物品模型。移植版的物品模型 JSON **故意不带 `display` 块**（1.7.10 从不查它，见 `TurborigItemRenderer:49`），所以 GROUND 是"手持/物品栏"那套摆放，放到世界实体上就放大了。
2. **原包模型本身是按大比例 authored**。测下来 RGD5 的 baked rig 高度是 **2.3125 格**；1.7.10 的 `RenderGrenade:51-53` 在画的时候额外乘了 `0.0625`。移植版的烘焙已经按格为单位，若再不加缩放就直接是 2.3 格。

## 修改

`GrenadeRenderer` 改为像子弹渲染器一样**直接画 baked rig**（`ModelCache.rigFor` + `RigRenderer.render`），并按定义自身的碰撞盒缩放：

```java
float rigHeight = Math.max(1.0E-4F, rig.maxY - rig.minY);
float wanted = Math.max(0.08F, Math.min(0.5F, type.hitBoxSize)); // 包里的 HitBoxSize
float scale = wanted / rigHeight;
pose.scale(scale, scale, scale);
```

RGD5：`0.5 / 2.3125 ≈ 0.216` → 世界高度 0.5 格，和实体碰撞盒一致；M67 同理。`SpinWhenThrown` 的自转保留，`stuck` 时冻结。

## 验证

`VerifyGrenadesAndDrops` 扩到 **71 断言**，新增：

- 渲染器必须调用 `PoseStack.scale`（按碰撞盒缩放），
- 渲染器不得再调用 `ItemRenderer.renderStatic`（不再走手持 GROUND 变换），
- RGD5 / M67 的 rig 必须烘焙出真实尺寸（高度 > 0.02）。

## 待确认

- 掉落枪实体（`GunItemRenderer`）目前仍走 `ItemDisplayContext.GROUND`。枪的物品模型在手持时≈1 格，放到地上大概率也偏大；若实机发现同样的放大，用同一套"直接画 rig + 按尺寸缩放"替换即可。
- 手雷落在草地上的静置姿态：直接画 rig 后模型原点在实体中心，视觉上可能半埋或半浮，必要时加 `pose.translate(0, 小偏移, 0)` 微调。
