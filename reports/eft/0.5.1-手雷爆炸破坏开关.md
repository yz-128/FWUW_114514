# 0.5.1 · 手雷爆炸的方块破坏开关

2026-10-20。用户反馈：RGD5 / M67 两只手雷都能破坏木制结构。RGD5 的定义是 `ExplosionBreaksBlocks false`，不该破坏方块。

## 原因

0.5.0 的爆炸调用把 `ExplosionBreaksBlocks` 塞进了**"是否点火"**那个布尔参数：

```java
level().explode(this, getX(), getY(), getZ(), type.explosionRadius,
        type.explosionBreaksBlocks, Level.ExplosionInteraction.TNT);
```

1.21.1 的签名是 `explode(source, x, y, z, radius, fire, interaction)`。方块破坏由最后一个 `ExplosionInteraction` 决定，`TNT` 永远炸方块；中间那个布尔只控制要不要生成火焰。所以 RGD5 的 `false` 只是"不点火"，木头照样被炸穿。

## 修改

`EntityGrenade.detonate()`：

```java
level().explode(this, getX(), getY(), getZ(), type.explosionRadius, false,
        type.explosionBreaksBlocks ? Level.ExplosionInteraction.BLOCK
                : Level.ExplosionInteraction.NONE);
```

- `ExplosionBreaksBlocks false`（RGD5、M83 烟雾、M84 闪光）→ `NONE`：不破坏任何方块，但**仍然伤害实体**（vanilla 爆炸的实体伤害与方块交互无关）。
- `ExplosionBreaksBlocks true`（M67 3s/4s）→ `BLOCK`：允许破坏方块。
- 火焰固定 `false`：1.7.10 的 `FireRadius` 是独立逻辑，本轮未移植，不该把"破坏方块"误当成"点火"。

## 回归

`VerifyGrenadesAndDrops` 增加 2 条字节码断言（65 断言）：

- `detonate` 里必须同时出现 `Level$ExplosionInteraction.BLOCK` 与 `NONE`（证明按定义分流）；
- 不得再出现 `TNT`（防回归成"一律炸方块"）。
