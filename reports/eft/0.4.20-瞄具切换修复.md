# 0.4.20 · 带全息镜时 G33 无法切换

2026-10-20。用户反馈："带了这个瞄具就不能切换了"——AK74M + SVD 侧导轨，同一挂位里放了 `G33Disabled` 和 `EOTech552`。

## 现象与复现

离线复现该装配（真 AK74M + `SVDLowSideMount` 槽位 6，槽位 0 内同时挂 `EOTech552` 与 `G33Disabled`）：

```
groups=3
  group0 aiming=G33Disabled   y=0.484 z=0.097 folded=true  cosight=true
  group1 aiming=EOTech552     y=0.485 z=0.000 folded=false cosight=false
  group2 aiming=6P1Sb2AK74Rearsight
```

折叠的 G33 自成一组、全息镜自成一组。**瞄准组是全息镜那一组时，折叠键没有任何反应**；只有切到 G33 自己那一组才能翻。

## 根因

`GunSightState.toggleTargets`（`GunSightState.java`）第二级配对要求"折叠镜展开后与当前瞄准镜**共线**"：

```java
if(shadow!=null && sameLine(group.aiming,shadowPoint(sight,shadow)))result.add(sight);
```

`sameLine` 的容差是显示用的 `LINE_EPSILON = 1e-5`。而这套真实挂位上，G33 的折叠位与全息镜差 **Δy=0.001、Δz=0.097 格**——差了四个数量级，永远判不共线，目标集为空，于是：

- `canChange(TOGGLE)` 在全息镜组里返回 false，按键静默无响应；
- G33 保持自己的组，展开后也不会并入全息镜的轴线，放大倍率自然用不上。

`cosight` 是内容包明写的配对（`G33Disabled → G33Enabled`、`G33Enabled → G33Disabled`），1.7.10 也是按 `ShadowType` 声明走的，不该再拿几何共线做二次否决。

## 修复

`GunSightState.java`：

1. 新增 `sameMount(a,b)`：两个 sight 共享同一父节点、同一 slot，就是同一挂位上的同一物理位置；
2. 第二级配对改为 **共线 OR 同挂位**，声明配对为准，几何共线只保留为快速路径：

```java
if(sameLine(group.aiming,shadowPoint(sight,shadow)) || sameMount(group.aiming,sight))result.add(sight);
```

不影响原有行为：同轴装配仍然走共线判定；非同挂位的折叠镜不会被误配。

## 回归

`tools/offline/VerifyGunSightState.java` 新增 6 条断言，直接搭用户这套真实装配：

- 真 `AK74M` + `SVDLowSideMount` + `EOTech552` + `G33Disabled` 同槽位；
- 选中全息镜组后 `canChange(TOGGLE)` **必须为真**；
- 触发 TOGGLE 后节点定义变成真实的 `G33Enabled`，且该镜子仍在枚举里。

`VerifyGunSightState` 断言数 69 → **75**。
