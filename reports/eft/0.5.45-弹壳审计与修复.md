# 0.5.45 · 各枪械弹壳审计与修复

日期：2026-10-22。需求：“各枪械蛋壳部分检查一下”，以及实机反馈 M1A 开火无弹壳、某个反射式瞄具不够亮。

## 一、弹壳系统审计结论

新增 `VerifyGunCasings`，按游戏真实的解析链（枪 → 弹匣类型 → 口径标签 → 子弹 → `ItsCase` 弹壳）审计 **全部已启用内容包**：

| 指标 | 数值 |
| --- | --- |
| 枪械定义 | **87** 把（69 自动/半自动、18 栓动） |
| 枪×弹药组合 | **5,154** 对 |
| 弹壳定义 | **9** 种（含 2 种加载时补全） |
| 结论 | 所有枪的每一种弹药都能得到真实弹壳；模型、贴图、比例全部可解析 |

发现并修复的问题：

1. **弹壳模型比例错误（所有枪）**：渲染时忽略了数据里的 `bulletScale`（EFT 0.044、Octagon 0.1），按 1.0 绘制，弹壳比正确尺寸大 **10–23 倍**。1.7.10 是先 `glScalef(bulletScale)` 再按 1/16 渲染，现在与之相同。
2. **部分枪不抛壳**：抛壳被 `GunAttachments.requirements(...,1)` 附件需求门控，1.7.10 只在“能自动射击”上做门控，不看附件需求。已移除该门控；M1A 属于这一类。
3. **两个弹壳定义在内容包里根本不存在**：EFT Reforged 的子弹写 `ItsCase 9x18BulletCase` / `12GBulletCase`，但 `run/flan` 全部 8 个包都没有这两个定义，1.7.10 下就是“什么也不抛”。现在加载时从真实弹壳补建：
   - `9x18BulletCase` ← 9×19 手枪弹壳（同族黄铜）；
   - `12GBulletCase` ← 9×19 弹壳放大 2.6 倍（霰弹壳尺寸）。
   补建类型只存在于 `BulletType.bullets`，不进 `InfoType.infoTypes`，不会变成物品/进创造模式。
4. **M1A 专项断言**：M1A 弹匣解析出的 7.62×51 子弹 `ItsCase` 指向 EFT 5.56 弹壳，审计逐条确认能拿到真实弹壳（非 null）。
5. **诊断日志**：新增 `[Casings]`（debug）与服务端/客户端抛壳链路、以及弹壳模型/贴图缺失的 **warn**（每种弹壳只报一次），实机再遇到无弹壳可直接从 `debug.log` 定位。

## 二、瞄具亮度

实机截图里的瞄具名 “JOKF-7” 在当前 8 个内容包里 **不存在**（全包检索无结果）；按名称与“皮卡丁尼兼容版”后缀，最可能是 **OKP-7 皮卡汀尼版**（`OKP7Pic`）。它的分划是 `DotModel EFTRAtt.OKP7PicDot LightTexture/OKP7PicDot 1`：

- 我们的渲染路径是 `entityTranslucentEmissive` + `LightTexture.FULL_BRIGHT`，与 1.7.10 的 `glowOnStatic()`（lightmap 240/240）**完全等价**；
- 分划尺寸另受 `reticleScale` 与屏幕像素自适应缩放影响，不会暗于原版。

如果更新到 0.5.45 后仍觉得暗，请告知确是哪个瞄具（F3+H 显示物品 ID）以及“暗”的是分划点还是瞄具本体，我按那个模型/贴图继续查。

## 三、部署说明（重要）

你的启动器实例里同时存在 `flansmod-0.5.44.jar` 和 `flansmod-0.5.44-classic.jar`（同一 modId，会撞车），而且它一直在跑 **0.5.38** 的旧会话。已处理：

- 两个 0.5.44 jar 移到 `mods/_backup/`；
- 旧 `flansmod-0.5.38-classic.jar` 也已在 `_backup/`；
- `mods/` 现在只有 **`flansmod-0.5.45-classic.jar`**（你原来用的是 classic 界面）；
- **重启客户端**后才会加载新构建。
