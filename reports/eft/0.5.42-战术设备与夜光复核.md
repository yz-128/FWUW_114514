# 0.5.42 · 战术设备（战术手电/激光）修复 + 夜光材质复核

日期：2026-10-22。需求：修战术设备（例如战术手电）；战术设备按键改用 **T**；并复核夜光材质是否真的全修好了。

## 一、战术设备

1.7.10 的战术手电/激光是「开关 + 发光模型」，不是动态光照：`Flashlight` 给出发光镜片模型，
`LaserPointer` 给出第一人称/世界两个发射器模型，开启时以满亮绘制。此前移植只解析了标志位，
模型引用被丢掉（`Flashlight ... <model>` 的模型 token 被当成数字强度），也没有开关和绘制。

已修复：

| 项 | 行为 |
| --- | --- |
| 数据解析 | `Flashlight <bool> [range] [lightModel]` 的模型引用正确读入；`LaserPointer true <fp> <tp>` 两个模型读入；模型 `laserFrom` 原点从原 class 提取 |
| 按键 | **T**：一次切换所有已安装的战术设备（有开→全关，全关→按枪上实装开） |
| 状态存储 | 存在枪的物品数据（`flansmodLightOn` / `flansmodLaserOn`），换枪/快捷栏/存档保留，随物品同步 |
| 同步 | 新增服务端权威 `GunTacticalPayload`：客户端请求、服务端校验并翻转枪上的开关 |
| 渲染 | 手持/世界/掉落物品路径：手电画 `lightModel`、激光画 `laserModelFP/laserModel`，满亮；激光按 `laserFrom` 偏移 |
| 本地预测 | 按键立即在本地切换，服务端确认后以服务端结果为准 |

验证：`VerifyTacticalDevices` **34 条**（真实 X400：手电范围 50、lightModel、两个激光模型；
夹具开关全开/全关；T 键、payload 接线），`VerifyMountedEmission` 见下节。

## 二、夜光材质复核（回答“确定全修好了吗”）

新增 `VerifyMountedEmission`：不再只测叶子函数，而是 **反射调用真实手持枪的 `renderAttachments`**，
用夹具枪挂上真实包里的夜光附件，记录每个顶点的 lightmap：

- 覆盖 **26 个真实夜光附件**（没有发光数据的普通附件不计）；
- 断言：body 顶点保持世界 lightmap（黑暗下为 0），**每一个夜光 quad 的顶点都被提升/满亮**，
  顶点数恰好等于 body + 夜光 passes，不多不少；
- **32,598 条**断言通过。

配合此前的验证：

| 路径 | 证据 |
| --- | --- |
| 改枪 GUI 预览（两种界面） | `VerifyGuiLegacyEmission` 各 **489,820** 项（45 个原模型 × 3 模式，真实顶点/颜色） |
| 单独手持附件/折叠瞄具 | `VerifyLegacyEmission` **34,212** 项（45/45 模型、lightmap 双通道、折叠 0/0.5/1 阶段） |
| 手持枪挂载附件（本轮补） | `VerifyMountedEmission` **32,598** 项 / 26 个附件 |

结论：**夜光材质在离线可验证的渲染路径上已全部覆盖**（数据解析 → 附件 body → 挂载渲染 → 折叠 → GUI 预览）。
未覆盖的是实机画面（本轮未启动游戏），以及原包里本来就没有 glow 调用的模型（不会被点亮，这是正确的）。
