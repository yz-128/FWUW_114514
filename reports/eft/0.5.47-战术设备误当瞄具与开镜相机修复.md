# 0.5.47 · 战术设备被当成瞄准具导致开镜镜头错位（根因修复）

日期：2026-10-22。你判断的方向是对的：**开镜相机确实错误用到了战术设备的位置**。这次找到的是数据+选择逻辑叠加出来的真实根因。

## 一、根因

legacy FMUM 包里的 `ANPEQ15.txt` 写着：

```
ShortName ANPEQ15
ItsType sight          ← 关键
AttachmentType flashlight
LaserPointer true EFTatt.LaserLightFP EFTatt.LaserLight
```

1.7.10 把照明/激光设备也归到 `sight` 渲染类别，所以数据里保留了 `ItsType sight`。

我们的 `GunSightState` 原来只按 `itsType == "sight"` 收集“可瞄准的瞄具”，于是 **AN/PEQ-15 也被收进瞄准组**。它挂在 ELCAN 同一根导轨线上、位置更靠前，组内按 x 从大到小排序后它排在第一 → `selectedGroup.aiming` 变成 AN/PEQ-15 → `LegacySightPose` 用它的坐标当 ADS 相机枢轴 → 相机跑到左侧导轨/枪体内部，于是看到“巨大的枪身/配件”。

这也解释为什么**装上战术设备后一开镜就变形**，而拆掉就正常：它改变了开镜相机用的那个“瞄具”。

## 二、修复

新增 `AttachmentType.isAimingSight()`：

```java
return "sight".equalsIgnoreCase(itsType) && !flashlight && !laserPointer;
```

含义：只要能发光/发激光，就不是用来“瞄准通过”的光学件。应用到：

- `GunSightState` 的瞄准组收集（相机枢轴、开镜选中项都基于它）；
- `FmumSightRenderer` 的 sight 渲染入口；
- `DebugCapture` 的瞄具采集。

修复后 AN/PEQ-15 仍是正常的战术设备（T 键开关、发光模型照常渲染），但**不再进入瞄准组**，开镜相机回到 ELCAN。

## 三、验证

`VerifyTacticalDevices` 增加到 **41 条断言**，其中专门复刻了这个 bug：

- ELCAN 与 AN/PEQ-15 挂在同一条导轨线上，设备位置更靠前 0.08；
- 断言瞄准组只有 1 组，且 `selectedSight` 是 **ELCAN**（修复前会是 AN/PEQ-15）；
- 另外检查所有 `flashlight/laserPointer` 的附件都不会成为瞄准具。

全量审计全部指向最终哈希（见下表）。

## 四、怎么测（你用的是项目里的 runClient）

你跑的是项目 `runClient`，不是启动器实例，所以：

1. **完全关闭当前 runClient**（结束进程，不是退回主菜单）；
2. 重新启动 `runClient`（`build/classes` 已经是 0.5.47 的新代码，不需要重新部署 jar）；
3. 同一把 M1A + ELCAN + AN/PEQ-15 开镜；
4. 若想确认新代码已加载，看 `run/logs/latest.log` 开头时间是否为新的，并可在开镜后查 `debug.log` 是否有 `[Reticle]` 行。
