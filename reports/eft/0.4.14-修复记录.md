# 0.4.14 · 两个已知缺陷的修复

2026-10-20。唯一工程 `E:/JAVAMCMODGJ/FLAN 移植i/flanmod-template-1.21.1`。承接 0.4.13 的两个缺陷：DS-IMPACTS-01 复核确认的水面落点判断，以及交接文档记录的 1.7.10 收枪差异。不改内容包，不改原包。

## 修复 1 · 弹壳落水仍响金属声

**现象**：0.4.13 只检查落点上方一格（`hit.block().above()`）有没有水。`waterlogged=true` 的方块自带水、上方一格却是空气，于是"水面层就是含水台阶/楼梯块"的池塘里，弹壳落在水下仍会响金属声。全量扫描：这类"带水 + 有可停落顶面"的方块共 263 种 / 8298 个状态。

**改法**：新增 `FmumCasing.submerged(BlockGetter, Vec3)`，同时检查落点所在格与上方一格，并且只有接触点低于该列流体表面时才算"水下"。

- 含水下半台阶：接触点 0.5 < 水面 0.888 → 水下，静音。
- 含水栅栏顶：接触点 1.5 高于该列水面 → 干燥，仍有声音。
- 池塘底：落点所在格是地板、上方一格是水，接触点位于水面之下 → 静音。
- 含水上半台阶：接触点抬到方块顶面，高于水面 → 仍有声音。

**顺序**：水面判断移到 `casing.audibleLanding` 之前，湿接触不再消耗"单壳最多 3 次"的配额。

**用例**（`VerifyImpactsAndLandings.casings()`）：池塘底、深水、干燥地面、含水下半台阶、含水上半台阶、含水栅栏顶共 6 条；另加 1 条字节码接线断言，确认 `CasingLandingSounds.play` 会调用 `FmumCasing.submerged`。

**离线注意**：`FluidTags.WATER` 在离线 bootstrap 下没有数据包绑定，测试里显式 `bindWaterTag()`；游戏内由原版数据包正常绑定，生产代码仍用标签判断（兼容被标为水的模组流体）。

## 修复 2 · 收枪后按瞄准键抬不起枪

**基准**：FMUM `ItemGun.java:198-202`——`operatingState == REST && manuallyRest && (fireKeyDown || aimKeyDown())` 时转 UNREST 并清掉手动收枪。

**现状**：开火路径已经在 `GunFiring.onTriggerPull` 里 `resume()`；瞄准路径没有，`GunActions.tick` 的 `!manualRest` 判断把 ADS 一直挡住。结果是按 O 收枪后右键无法抬枪，只能先开一枪。

**改法**：新增 `GunActions.dismissManualRestOnAim(GunActionState, boolean aiming)`，在 `tick` 计算瞄准进度之前调用，条件与 1.7.10 一致（REST + 手动收枪 + 瞄准键按下）。双侧都跑：客户端本地立即生效，服务端收到 `GunAimPayload` 后同一 tick 生效。

**用例**（`VerifyGunActions.clocks()`）3 条：收枪到 progress=1 → 按住瞄准 → `manualRest=false` 且 `operation=UNREST`（不是只翻标志位）；再收枪、松开瞄准 → 仍是 REST。
