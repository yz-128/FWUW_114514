# 0.5.27 · 修复"打一枪就过热"

日期：2026-10-22。用户反馈：默认参数下第一枪就触发过热锁火。

## 一、原因

`BarrelHeat.lockOnOverheat(heat, lockTicks)` 的原实现是：

```java
return overheated(heat) ? Math.max(lockTicks, 1) : lockTicks;
```

调用方为了"过热时用枪定义里的锁时长"，把 `gun.heatLockTicks`（默认 40）作为**当前锁**传了进去：

```java
data.heatLockRight = BarrelHeat.lockOnOverheat(data.heatRight,
        data.heatLockRight > 0 ? data.heatLockRight : gun.heatLockTicks);
```

于是**没到过热线时也会原样返回 40**——每开一枪就给自己上 40 tick 锁，表现为"一枪就过热"。

## 二、修复

把两个概念拆开：

```java
public static int lockOnOverheat(float heat, int lockTicks, int armTicks)
{
    return overheated(heat) ? Math.max(lockTicks, Math.max(1, armTicks)) : lockTicks;
}
```

- `lockTicks`：当前正在运行的锁（正常为 0）；
- `armTicks`：过热时才启用的新锁时长（枪定义的 `HeatLockTicks`）；
- 未过热时**原样返回当前锁**，普通射击不会上锁。

`GunFiring` 的两个调用点改为传 `(热量, 当前锁, gun.heatLockTicks)`。

## 三、验证

- `VerifyBarrelHeat` 增加 2 条断言（共 **55 条**）：
  - `lockOnOverheat(0.012F, 0, 40) == 0` —— 默认一枪不锁；
  - `lockOnOverheat(0.5F, 0, 40) == 0` —— 未到过热线不锁；
  - 过热时才按 `ARM` 上锁，且已有更长的锁不会被缩短。
- 机制审计（55 + 65 条）、改枪（含 GPU 深度）、瞄具 GPU、着弹点全部通过，同一哈希
  `986A25B74973E1CAFC785328E4D76B66EB1ADFB88A40453A44DF27F3FB5F89E5`。
