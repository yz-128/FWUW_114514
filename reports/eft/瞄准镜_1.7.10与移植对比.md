# 瞄准镜渲染：1.7.10（FMUM）与移植版对比

日期：2026-10-23。对照对象：同一把 M1A、同一瞄具（ELCAN SpecterDR，`SeecterDR1x4x`）开镜画面。

> ## ⚠ 更正（2026-10-23，按 FMUM-1710 原码复核，GPT 交接）
>
> 本文早先的以下结论**已被推翻**，保留原文只为历史痕迹，不得再作为修改依据：
>
> 1. **“原版分划/遮罩只画在普通手空间，应删除镜内烘焙” — 错。**
>    `RenderGun.java` 的 `onScopeLayerRendering >= 0` 分支（约 1022–1219 行）绘制虚拟枪、分划与黑边，
>    `renderScopeFramebuffer`（约 290 行）随后把它复制成镜内纹理。普通手部与 scope layer 是两条分支，
>    必须分别对照。
> 2. **“镜内分划缺乘 pupilDistance” — 错。**
>    普通分支约 809/827 行用 `reticleScale * pupilDistance`；scope 分支约 1056/1075/1082 行调用
>    `SightCoor.getDivisionScale()`，后者只有 `relativeReticleSize` 时才乘 `FOVZoom[0]/FOVZoom[step]`，
>    **没有**通用 pupil 乘子。不要给 scope 路径统一补乘眼距。
> 3. **“遮罩缩放缺 factor>1 分支” — 不成立。**
>    旧式 `baseScale * (factor>1 ? 1 : factor)` 与当前 `baseScale * min(1,factor)` 等价，
>    不是已证实差异或根因。
>
> 此外：原版 scope layer 会在物镜重定位后重新绘制虚拟枪体；当前二次 `renderLevel` 使用
> `renderHand=false`，只烘分划，**并未完整复现该分支**。因此不能说“流程完全等价”。
>
> 当前源码状态：reticle 烘入 IMAGE；black mask 的 bake 仍关闭；`projectCamera` 仍用固定 0.4 作深度，
> 它是旧局部坐标基准，**不等于**已证明的现代相机 Z 深度，需按原版 scope 坐标链取实际深度。
> 采样方向与 `imageUv()` 是否必要，仍需用轴向标记的实机探针验证。

## 一、画面差异（一眼可见）

| 项 | 1.7.10（左） | 移植版（右，当前） |
| --- | --- | --- |
| 镜片内的世界 | 填满整个镜片开口，正常放大 | 只有中间一个**小圆**有画面，周围黑 |
| 分划 | 细十字 + 小 chevron，落在镜片中心 | 十字线贯穿整个镜片/黑区，中心有 chevron |
| 黑边 | 只在镜筒/镜片边缘 | 镜片内出现整圈黑 + 之前的两片“翼” |
| 过渡 | 镜片图与镜筒自然衔接 | 镜内图、遮罩、镜筒边界互相穿插 |

## 二、架构对比

```
1.7.10（FMUM）                              移植版
────────────────────────────────────        ────────────────────────────────────
方形 framebuffer（1024×1024）                TextureTarget（屏幕分辨率）
fovSetting = base / (FOVZoomLevel×pupil)    nativeFov 同公式 → imageFov/renderFov
renderWorld → copyTexImage2D                 renderLevel → copySquareColor → 动态纹理
        │                                            │
手部 pass 里：                                合成 pass 里：
  玻璃：整块 scopeGlassModel                   玻璃：renderLensSurface
        原始 UV + 纹理 + glColor3f(alpha)              LENS 层（采样动态纹理）
        glScalef(scopeGlassModelScale)                imageUv 重映射 + alpha 亮度
        （无面过滤、无 UV 重映射）                       （原来只画 nx<-.9 的面）
  分划：手空间固定 0.4F 基准                    分划：ScopeReticleRenderer
        glScalef(1, reticleScale×pupilDistance)      scopeImage() 投影进方形镜内图
        insideSightBorder 求交后画                     aperture 裁剪后贴玻璃
  遮罩：最后画                                   遮罩：ScopeMaskRenderer
        translate(scopeMaskXTrans, 0.4+transY, transZ)  frame() 算 scale/depth/y/z/fov
        glScalef(1, getScopeMaskScale(), ...)          再投影进镜内图、裁剪贴玻璃
        整块 blackMaskModel.render(f)                  overlay(skin) 叠层
```

## 三、逐项对比表

| 环节 | 1.7.10 | 移植版 | 影响 |
| --- | --- | --- | --- |
| 镜内相机 | 临时改 `fovSetting = base/(FOVZoomLevel×pupilDistance)`，方形 display 尺寸 | 嵌套 `TextureTarget`，`nativeFov` 同公式，`squareRenderFov` 方形校正 | FOV 公式一致（日志 `imageFov=2.82°` 即该结果） |
| 玻璃覆盖 | `scopeGlassModel.render(f)` **整块** | 先只画 `nx<-.9` 的 29 个面；刚改为整块 | 之前只剩中间小圆，外圈黑 |
| 玻璃 UV | 作者原始 UV，直接采样方形镜内图 | `imageUv()` 重映射到“方形图片基准” | UV 基准可能把图缩到中间（当前小圆的主因之一） |
| 玻璃亮度 | `glColor3f(alpha,alpha,alpha)` + `glowOnStatic()` | LENS 顶点色 `brightness=alpha`，不写深度 | 等价，但 LENS 是 opaque；alpha<1 时是变暗而不是透明 |
| 分划坐标空间 | **手空间**：瞄准枢轴后固定 `0.4F` 平面 | **镜内图空间**：投影进方形图再贴玻璃 | 2.82° FOV 下投影焦距≈40，分划偏移被放大 → 巨大黑块/贯穿线 |
| 分划缩放 | `reticleScale × pupilDistance` | 先 `reticleScale×pupil` + `stableReticleScale`；scope 路径里 `ScopeReticleRenderer` 只乘 `reticleScale` | scope 路径少乘 pupil，尺寸不一致 |
| 分划裁剪 | `insideSightBorder` 判可见，不做多边形裁剪 | 投影后 `clip()` 到玻璃 aperture | 裁剪算法不同，边缘行为不同 |
| 遮罩坐标 | 手空间：`y=0.4F+scopeMaskTransY`，`x=scopeMaskXTrans`，`z=scopeMaskTransZ` | `frame()` 换算出 depth/y/z 再投影进镜内图 | 空间不同；遮罩几何被投进孔径 → 黑翼 |
| 遮罩缩放 | `getScopeMaskScale() = scopeMaskScale×FOVZoom[0]/FOVZoom[step]/pupilDistance`（>1 分支） | `scopeMaskScale×first/raw/distance×factor` | 近似但少了 1.7.10 的 >1 分支细节 |
| 绘制顺序 | 玻璃 → 分划 →（coated glass）→ **遮罩最后** | 玻璃 → 分划 → 遮罩（同序）；刚实验改为 遮罩→玻璃→分划 | 顺序曾对，但空间错才是黑翼主因；实验顺序只能止血 |
| 黑玻璃回退 | 整块 glass + `DefaultBlack` | 只画 `nx<-.9` 面（刚改为整块） | 未开镜时边缘可能露空 |
| 深度/混合 | 固定管线，GL 深度测试 + glow 状态 | LENS：COLOR_WRITE 不写深度；overlay：translucent emissive，LEQUAL，不写深度；`composite` 统一 depthMask(false) | 层间不被互相遮挡，靠绘制顺序混合 |
| 眼点 | 固定 `viewPoint = (-81.5/160, 0.4, 0)` | 实际相机位置 `eyeInGunSpace` | pupilDistance/alpha 的基准不同，但公式结构一致 |

## 四、公式对照

| 量 | 1.7.10 | 移植版 |
| --- | --- | --- |
| FOVZoom | `FOVZoomLevel[step] × pupilDistance` | `nativeFov = base / (raw × distance)` |
| 分划缩放 | `reticleScale × pupilDistance` | scope 路径：`reticleScale`（缺 pupil）；非 scope：`reticleScale×pupil` + 2px 下限 |
| 遮罩缩放 | `scopeMaskScale × FOVZoom[0]/FOVZoom[step] / pupilDistance` | `scopeMaskScale × first/raw / distance × factor` |
| 遮罩偏移 | `tan(角度)×scopeMaskMultTransY/Z`，基准 y=0.4 | `maskOffset()` 同来源，基准是实际 eye |
| alpha | `1-(transY²+transZ²)/divisor` | `ScopeEyeRelief.picture` 同公式（已移植） |

## 五、结论

1. **FOV、alpha、pupilDistance 的公式基本一致**，不是这次“黑翼/小圆”的根因。
2. 根因是**坐标空间选错**：1.7.10 的分划和遮罩画在**手空间**（固定 0.4 平面 + 相应缩放），移植版把它们**投影进镜内图空间**；在 2.82° 这种小 FOV 下，投影焦距极大，导致遮罩/分划被放大并裁剪成黑色多边形 —— 就是黑翼和贯穿线。
3. 玻璃“小圆”是另一个问题：移植版对玻璃做了 **UV 重映射 + 面过滤**，1.7.10 是**整块模型 + 原始 UV**。整块绘制已改，UV 重映射还应去掉。
4. 正确的对齐方式是照 1.7.10 重写合成：
   - 玻璃：整块模型、原始 UV、纹理直接采样方形镜内图；
   - 分划：手空间，`0.4F` 基准，`reticleScale×pupilDistance`；
   - 遮罩：最后画，`(scopeMaskXTrans, 0.4+transY, transZ)` + `getScopeMaskScale()`；
   - 删除/降级 `ScopeReticleRenderer`、`ScopeMaskRenderer` 里的“投影进镜内图”路径。
