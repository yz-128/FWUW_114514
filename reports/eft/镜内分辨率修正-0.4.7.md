# 镜内分辨率与光学路径修正 0.4.7

日期：2026-10-19。唯一工程：`E:/JAVAMCMODGJ/FLAN 移植i/flanmod-template-1.21.1`。
产物：`build/libs/flansmod-0.4.7.jar`（Java 21 / NeoForge 21.1.250）。

## 结论先说

0.4.4 的镜内画面是**从已经渲染好的世界画面中央裁一小块再拉伸**贴到镜片上。这条路拿不到任何新细节：
4 倍镜只取屏宽的约五分之一，1080p 下大约 383×215 像素被拉到 709×391 显示。**这就是"镜内分辨率低"的根因**，
不是拷贝缓冲区太小。实测数字（PSO1，1920×1080，4 倍）：

| 量 | 值 |
| --- | --- |
| 椭圆瞳孔距离 `pupil` | 0.1100（随眼睛位置变化） |
| 旧算法除数 `raw × pupil` | 4.402 |
| 旧裁切比例 | 0.1995 |
| 旧可用源像素 | 383 × 215 |
| 镜片在屏上尺寸 | 709 × 391 |
| 插值拉伸倍数 | 1.85 × |
| 新方案源像素 | 1920 × 1080（整帧，1:1） |

## 三种实现对照（都读过源码）

| 实现 | 镜内画面从哪来 | 分辨率 |
| --- | --- | --- |
| 1.7.10 FMUM `RenderGun.renderScopeFramebuffer` | 用 `fovSetting = 原FOV/(倍率×瞳距)` **第二次渲染世界**，写进 `scopeGlassResolution = 256` 的固定 FBO | 256×256，最糊 |
| TACZ 1.20.1 `CameraSetupEvent.applyScopeMagnification` | **直接把世界相机 FOV 拉近**；手持物用另一套 FOV 保持原尺寸；镜筒用模板缓冲挖孔 | 主渲染原生分辨率 |
| FMU 2.0 1.21.1 `ModClient.cameraFov` | 同上，世界 FOV 除以倍率；镜内靠全屏 `ZoomOverlay` 贴图 | 主渲染原生分辨率 |

两种现代实现都不裁帧。本版按这条路重做。

## 改了什么

1. **世界相机按倍率拉近**（`GunDetails.fov` + 新增 `ScopeMagnification`）。
   不再从成品画面取裁剪。手持物的 FOV 不加倍率，所以枪和镜保持物理尺寸，只有镜外世界被放大。
   `AimState.blend` 仍然驱动过渡，开镜过程是连续的。

2. **倍率语义改正**（`AttachmentType.ZOOM_LEVEL_SCALE`）。
   内容包的 `ZoomLevel` 权重是名义倍率的 10 倍：PSO1 写 `40 0.6` 是 4 倍镜，NF7x 写 `70 0.3` 是 7 倍镜，
   Octagon 的变倍镜写 `87.75 … 39` 对应 8.8 倍到 3.9 倍。除以 10 就得到作者给瞄准镜命名时用的倍数。
   旧代码乘的是瞳距，对直装的 PSO1 恰好接近，但 NF7x 会算成 0.70 被钳到 1 倍（等于没放大），
   CICND 的 `48.75 × 0.63` 会算成 30 倍。这是内容包实测值，不是猜的。

3. **镜片改为 1:1 采样，不再裁切**（`ScopeWorldTexture` + `FmumSightRenderer.renderLens`）。
   世界已经按放大后的 FOV 渲染过，所以镜片只需要把它正后方的像素原样显示出来：
   每个顶点的纹理坐标就是它自己的屏幕位置（NDC → 0..1），没有中心偏移、没有拉伸。
   这同时解决了另一件事——EFT 的瞄具模型在目镜处有一块不透明挡片（`PSO1` 的 `x=0.938` 前后端面），
   不画镜片的话玩家会正对这块挡片，什么都看不见。

4. **未选中/未开镜时的镜片仍是黑的**。1.7.10 在没有 FBO 绑定时画 `DefaultBlack`；
   现在的行为一致，也避免了腰射时放大的世界从镜筒里漏出来。

5. **准星投影用同一个 FOV**。`ScopeMagnification.scopeFov()` 返回世界实际渲染用的角度，
   `ScopeReticleRenderer` 用它做透视投影，准星和画面不会随时间漂移。

## 目镜几何实测

世界整屏放大后，镜片是否盖得住画面取决于目镜的角半径：

| 瞄具 | 倍率 | 目镜半角 | 放大后半视场 | 目镜盖满屏幕 |
| --- | --- | --- | --- | --- |
| PSO1 | 4.000 | 14.682° | 9.929° | 是 |
| SeecterDR1x4x | 4.875 | 28.798° | 8.174° | 是 |
| SeecterDR1x4x（低档） | 1.550 | 28.798° | 24.311° | 是 |
| NF7x | 7.000 | 0.000° | 5.712° | 否 |
| G33Enabled | 3.900 | 0.000° | 10.178° | 否 |

NF7x 和 G33 报 0°，原因是它们的 `pupilRefCenter`（`[-1.9375,0,0]` / `[-1.40625,0.390625,0]`）
把虚拟眼点推到了镜片平面前面，探针测不到角半径。这两种镜的镜片模型是共用的
`EFTRAtt.PSO1Glass`，目镜本身有实体，所以实机观感需要进游戏确认一次。

## 顺手修的工具问题

`tools/offline/RunEftAudit.ps1` 在本机无法运行，与本轮光学改动无关，但挡住了回归：

- Windows 命令行长度上限 + PowerShell 5.1 对含空格参数的处理，导致 14 KB 的 classpath 被拆断。
  改为 javac/java `@argfile`。
- argfile 用 ASCII 写出时会把工程路径里的中文目录名变成 `???`。改为把工程内条目写成相对路径，
  只留下纯 ASCII 的 jar 路径。
- `$ErrorActionPreference = 'Stop'` 会把 JVM 写到 stderr 的警告当成终止错误。改为 `Continue`，
  每一步仍按 `$LASTEXITCODE` 判断。
- `VerifyEjections` 还在调用抛壳物理改造前的 `tick()` 无参签名（本轮之前就坏了），已更新；
  寿命断言改为按倍率比较，因为延长蛋壳存在时间是明确需求，不再要求逐 tick 等于原版。
- 新增 `VerifyScopeZoom / VerifySightPicture / VerifySightAlignment / VerifyScopeReticles / VerifyCasingPhysics`
  五个入口，避免这些检查只存在于临时脚本里。
