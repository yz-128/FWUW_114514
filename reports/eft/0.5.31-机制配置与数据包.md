# 0.5.31 · 机制开关 + 配置界面 + 数据包覆盖

日期：2026-10-22。需求：在 mod 设置加开关，并让参数可以通过配置界面和数据包调整。

## 一、三个入口

| 入口 | 位置 | 能改什么 |
| --- | --- | --- |
| **游戏内设置界面** | 主菜单 → 模组 → Flan's Mod → **Config** | 三个开关 + 所有数值滑条 |
| **配置文件** | `config/flansmod-common.toml` | 同一组键值，热重载 |
| **数据包** | `data/<命名空间>/flansmod/mechanics/settings.json` | 覆盖任意键（`/reload` 或进世界生效） |

**优先级：数据包 > 配置文件 > 内置默认值。** 数据包不写就完全按配置；配置文件不写就完全按内置默认。

## 二、可调项（默认值）

```toml
[mechanics]
    enabled = true                  # 总开关：关掉等于回到只有 1.7.10 行为
    barrelHeatEnabled = true        # 枪管过热开关
    blockBreakingEnabled = true     # 子弹破坏方块开关

    [mechanics.barrelHeat]
        heatPerShotScale = 1.0      # 每发热量倍率
        heatCoolRateScale = 1.0     # 冷却速度倍率

    [mechanics.blockBreaking]
        healthPerHardness = 4.0     # 方块血量 = max(0.5, 硬度) × 此值 × 材质韧性
        plasticToughness = 5.0      # 泥土/沙/沙砾/黏土/灵魂沙/雪
        glassToughness = 0.35
        woodToughness = 1.0
        stoneToughness = 1.5
        metalToughness = 2.5
        maxSoftBlocksPerShot = 4
        maxBlocksPerShot = 6
```

## 三、实现

| 文件 | 作用 |
| --- | --- |
| `common/config/MechanicsConfig.java`（新） | `ModConfigSpec`（COMMON）：开关、倍率、方块血量/韧性/上限；提供 `register(ModContainer)` |
| `common/MechanicsSettings.java`（新） | 运行时数值层：内置默认 → 配置 → 数据包覆盖，重复应用；无 FML 依赖，供离线断言使用 |
| `common/MechanicsData.java`（新） | 数据包监听器（`SimpleJsonResourceReloadListener`，目录 `flansmod/mechanics`），扁平/嵌套 JSON 都支持；`/reload` 生效并打日志 |
| `client/gui/MechanicsConfigScreen.java`（新） | 模组列表里的 Config 界面：开关按钮 + 数值滑条，Done 保存并立即生效 |
| `common/FlansMod.java` | 注册配置 + 注册 `IConfigScreenFactory`（客户端） |
| `BarrelHeat` / `BlockDamage` / `BulletBlockPenetration` / `GunFiring` / `PlayerData` | 改为从 `MechanicsSettings` 读开关、倍率、血量、韧性与上限 |

开关行为：
- `enabled=false` → 枪管不升温/不锁火、子弹不破坏方块（与 0.5.23 前一致）；
- `barrelHeatEnabled=false` / `blockBreakingEnabled=false` → 只关对应机制；
- `-Dflansmod.mechanics=off` 仍可用于脚本化测试，强制关闭枪管过热。

## 四、数据包示例

文档：[docs/机制配置与数据包.md](../docs/机制配置与数据包.md)；


嵌套写法也接受（`{"mechanics":{"blockBreaking":{...}}}`）。

## 七、说明

- 配置文件在首次启动时由 NeoForge 生成（`config/flansmod-common.toml`），当前仓库里没有提交它；
- 多人游戏：配置为 COMMON 类型，服务端数值决定实际判定；数据包覆盖在服务端生效，客户端以服务端结果为准（客户端只做预测/HUD）；
- 配置界面在 `classic` 版 JAR 内同样可用（界面代码在主源集）。
