# 0.5.40 · 夜光材质收尾 + 机制改动合并

日期：2026-10-22。本轮接手 GPT（Codex）未完成的夜光（emissive）收尾，并把 DSH 这边的机制改动一起合并进最终产物。
**未启动/关闭游戏，未改内容包，未改协议（15）。**

## 一、接手时遗留的问题

1. GPT 已完成原包夜光材质识别与接线（`ModelGeometry.GlowLight`、`BytecodeModel` 解释器、`BakedRig.EmissivePass`、
   `TurborigItemRenderer` 附件表面、GUI 预览、`SightFoldRenderer`），并自测 `VerifyLegacyEmission` 34,212 项通过；
   但其自述「最终 JAR 的构建和整体报告由主线程统一完成」。
2. 旧的 `VerifySightFoldPlayback` 仍是夜光改动前的断言（期望折叠端点恰好等于 `attachmentModel` 全部几何），
   夜光组加入后光学审计在此失败——这是 0.5.39 之后无法继续出包的阻塞点。
3. DSH 的「关闭方块破坏后不再显示裂纹 + 旧版玻璃必碎独立开关」尚未进入任何已发布产物。

## 二、本轮完成

1. **更新 `VerifySightFoldPlayback` 到夜光语义**（本轮唯一改动的验证器）：
   - phase 0 期望 = 渲染计划（`SightFoldGeometry.plan`）中每个可见来源 piece 的顶点；
   - phase 1 期望 = 目标 rig 的 `attachmentBody(mode)` + `emissivePasses(mode)` 精确顶点集；
   - 新增端点总顶点数断言（body + 夜光 passes 每 quad 4 顶点，不重复）；
   - 仍保留镜像 phase 的顶点数与位置一致性检查。
   结果：该验证器断言数 538,125 → **543,505**，光学审计全绿。
2. **确认 GPT 的 GUI 夜光接线已在两种界面落地**：`GunModificationPreview.renderMesh(...,fireMode)` 现代/classic 均存在；
   `VerifyGuiLegacyEmission` 两版各 **489,820** 项通过（45 个原模型 × 3 模式，真实预览顶点/颜色）。
3. **合并 DSH 机制改动**（0.5.39 之后新增）：
   - `blockBreakingEnabled=false` 时命中方块**不再出现裂纹**（只保留弹着点/命中音），软掩体也不再被 chip；
   - 新增独立开关 `legacyGlassBreaking`（默认 true，控制旧 `BreaksGlass` 玻璃必碎），配置界面第 4 个开关 + 数据包键；
   - 继承 0.5.39 的按枪独立过热、卡弹 + G 退弹、冷却倍率默认 1.25、默认值表。
4. **统一构建与全量审计**（最终 JAR 见下）。
