# 0.5.12 · 快慢机三个状态同时出现在枪上

日期：2026-10-21。用户指出：打开改枪界面时，AK74M 的模型上同时出现了**三个状态的快慢机**（保险 / 半自动 / 全自动三个位置的拨杆叠在一起）。修的是渲染，不是数据。

## 一、1.7.10 的行为

`ModelGun` 把快慢机的所有位置放在一个数组里，只画当前模式那一段：

```java
// FMUM ModelGun.java:161-166
public void renderSwitch(int numToRender, float f) {
    if(numSwitchModel != 0)
        for(int head = numToRender * numSwitchModel, i = head + numSwitchModel; --i >= head; switchModel[i].render(f));
}
```

- `numSwitchModel` = 每个状态占多少个 renderer；模型通常写 `numSwitchModel = switchModel.length / 3`。
- `numToRender` = `fireModeNum`：改装界面里 `GunsmithPreview:109` 会先 `RenderGun.fireModeNum = GunType.getFireModeNum(GunType.getStates(stack))` 再渲染（`renderGunModifying` 里也显式 `gunModel.renderSwitch(fireModeNum = …, f)`）。
- AK74M 的模型：`switchModel` 数组 **48 项**，`numSwitchModel = 48 / 3 = 16`，即 3 个位置 ×16 个 renderer。

## 二、移植版的问题

- 烘焙时 `switchModel` 数组被当作一个普通 part（`switchModel`），48 个 renderer 的四边形全部进 `quadsByPart`；
- 渲染时（手持/第三人称 `renderAnimatedParts`、改装预览 `GunModificationPreview.renderMesh`）都是**把整个 part 画完**；
- 移植版没有 `renderSwitch` 的切片逻辑（全仓 grep 不到 `switchModel` 引用），所以三个位置同时可见。

## 三、改动

| 文件 | 改动 |
| --- | --- |
| `loader/ModelGeometry.java` | `Model` 新增 `switchModelGroups` / `slideSwitchModelGroups` |
| `loader/BytecodeModel.java` | 标量捕获新增 `numSwitchModel` / `numSlideSwitchModel`（类是 `switchModel.length / 3`，所以捕获到的是除数 3） |
| `loader/BakedRig.java` | 烘焙后按 `switchModel#i` 建索引；新增 `switchModelsPerState()`、`switchModelSlice(fireMode)`、`switchModelHidden(fireMode)`、`slideSwitchModelSlice(...)` |
| `common/types/GunType.java` | 新增 `fireModeIndex(ItemStack)` = 当前模式在包内 `Mode` 列表中的下标（即 1.7.10 的 `fireModeNum`） |
| `client/render/TurborigItemRenderer.java` | 手持/第三人称：`switchModel` 与 `slideSwitchModel` 只画当前模式那一段；`slideSwitchModel` 跟随滑套位移 |
| `client/gui/GunModificationPreview.java` | 预览绘制与鼠标拾取都跳过其它位置的快慢机网格 |
| `tools/offline/RenderTarkovGunsmithLayout.java` | 离线预览生成器同步过滤，产出图与实机 UI 一致 |

顺序按包内 `Mode` 行：AK74M 是 `Mode fullauto semiauto safe` → `fireModeIndex` 0/1/2 对应三个位置。

## 四、验证

**新增 `VerifyFireModeSelector`（31 断言，离线）**：

- AK74M 烘焙结果：`switchModelGroups=3`、索引到 **48** 个 renderer、每位置 **16** 个；
- 三个 slice 都被切出、大小相同、两两不相交、并集恰好覆盖整个数组；
- 位置 0 与位置 1 是不同的网格（不是同一批四边形）；
- `switchModelHidden(0)` 恰为另外两个位置的总和；`-1` 表示不过滤（离线检查用）；越界模式会夹到真实位置；
- `fireModeIndex`：三个模式分别映射到 0/1/2；
- 弹匣（`6L20_545x39_30Rounds`）没有 selector：`switchModelsPerState()==0`、隐藏集为空；
- 字节码接线：`BytecodeModel` 读 `numSwitchModel`、`BakedRig` 暴露切片、`TurborigItemRenderer` 与 `GunModificationPreview` 都调用切片接口、`GunType` 有 `fireModeIndex`。

## 六、未覆盖

- `slideSwitchModel`（滑套上的快慢机）已按同一机制处理，但现有内容包里没有模型使用它，属预置能力；
- 配件自身的 `fireModeModel`（例如 Beretta / Glock 滑套上的模式指示）走的是 `ModelAttachment` 的另一条分支，本轮未动；需要的话可以按同样思路补（配件只画 `attachmentModel`，目前这些条件网格不被绘制）。
