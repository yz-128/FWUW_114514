### A. 复核双界面渲染，再由用户实机验收

本轮最终 JAR 离线验证通过：modern 10 组 / 50580 项，classic 7 组 / 23029 项；两者各含 6 个真实装配 GPU 案例 / 87 项，均为 0 findings。modern 另保留 7 张离线布局预览。两份产物的 294 / 292 个生产 class 与各自编译输出一致，284 个共有非 Preview/Screen 类逐字节一致，变体差异仅有 11 项 UI 文件。证据位于 `reports/eft/gunsmith-tarkov-0.5.22/`；固定工具在旧 0.5.21 上的失败对照保存在其 `previous-0.5.21/` 子目录，不改标为当前结果。

`tools/offline/RunGunsmithAudit.ps1` 现在对 modern 和 classic 分别验证实际 GPU 网格层、深度守卫及当前快慢机切片；modern 另保留布局、拾取、导轨拖动和 7 张离线布局预览。最终结果以 0.5.22 报告及各变体绑定的 JAR 哈希为准。人工验收重点：机匣内部不透出、快慢机仅显示当前状态、枪体不再被重复光照压黑、最大放大后挂点标牌仍可见、转动后遮挡正确；modern 的挂点/结构树联动、可调配件拖动、搜索与 compact 库存继续正常。保留服务器校验、先拆后装、子树与多件同槽规则。

当前仍是单活动镜内目标，没有将虚拟枪体和效果绘入镜内世界。二次世界渲染改为在实时手部姿态可用后执行，已保存/恢复 FBO、视口、投影及相关 GL 状态，但与 accelerated 手部渲染器的嵌套 `renderLevel` 交互仍需实机确认。原 FMUM 每镜独立目标的完整流程、腰射/偏轴行为及 Iris 光影和 Fabulous 的单次世界渲染兼容路径应按独立任务接续，不能称为整套照搬。

## 常见陷阱速查

| 现象 | 原因 |
| --- | --- |
| 经典改枪界面透出内部 / 快慢机重叠 | classic 有独立 Preview，须接入同一深度层与模式筛选，并单独跑 GPU；共享后端通过不代表 GUI 接线通过 |
| 镜内糊 | 别裁成品帧，要放大世界 FOV |
| 开镜瞄具跑到屏幕外 | 枢轴用了固定 0.4，要用真实相机位置 |
| 红点镜开镜没准星 | 被当成"镜筒"跳过了 |
| 对着草自动收枪 | 用了 `OUTLINE`，要用 `COLLIDER` |
| 倍率不对 | 原生镜内 FOV 使用 `baseFov / (rawZoom × 实测眼距)`，不要把名义倍率兼容公式套到该路径 |
| 旧 EFT 瞄具字段全丢 | 需要 `opticalAliases` 别名映射 |
| CI 构建失败 | `build.gradle` 不能引用仓库外路径 |
| 中文路径导致工具炸 | argfile 用相对路径，别用绝对路径 |
| 弹壳落水还在响 | 只看 `above()` 不够，要按接触点高度与流体表面对比（`FmumCasing.submerged`） |
| 收枪后右键抬不起枪 | 瞄准路径没有 `resume()`，不能只靠开火解除（`GunActions.dismissManualRestOnAim`） |
